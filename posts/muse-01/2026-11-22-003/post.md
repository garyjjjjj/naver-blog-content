AI 에이전트 뜻을 한 줄로 말하면, 답을 내놓는 데서 끝나지 않고 도구를 써서 일을 끝까지 해내는 AI이다.
요즘 뉴스마다 에이전트, 에이전틱 AI, 컴퓨터 유즈가 쏟아지는데, 세 말이 같은 뜻이 아니라서 헷갈린다.
이 글은 Anthropic 공식 문서(2024-12-19)를 기준으로 세 용어를 나눠 정리한다.

```blog
type: text
runs:
  - text: "AI 에이전트는 모델이 다음 단계를 스스로 정해 도구를 쓰고 목표를 끝내는 시스템이고, 에이전틱 AI는 에이전트와 워크플로우를 함께 아우르는 넓은 말이며, 컴퓨터 유즈는 에이전트가 화면을 보고 클릭하고 입력하는 손에 해당한다."
    style: {bold: true, color: "#007aa6"}
```

에이전트를 실제로 어떻게 쓰는지 궁금하면 [클로드 사용법 지도](https://blog.naver.com/3700708/224485709482) 글에서 묻고 만들고 맡기는 순서를 확인할 수 있다.

![책상 왼쪽의 스마트폰 채팅 화면과 오른쪽에서 서류를 정리함에 옮기는 작은 로봇 팔](images/02-img1.jpg)

스마트폰 채팅창과 서류를 옮기는 로봇 팔이 나란히 놓여 있다

```blog
type: text
runs:
  - text: "AI 에이전트 — "
    style: {bold: true, color: "#ff008c"}
  - text: "일을 끝내기 위해 다음 단계를 스스로 정하고 도구를 부르는 시스템이다. Anthropic은 에이전트를 '스스로 단계를 계획하고 파일을 읽고, 명령을 실행하고, 코드를 고치는 도구를 부르는 애플리케이션'이라고 설명한다(Anthropic, 2024-12-19)."
```

판정 기준은 하나이다.
모델이 다음 단계를 스스로 정하는가.

챗봇은 질문마다 사람이 다음 단계를 정한다.
답을 내놓는 데서 역할이 끝난다.

에이전트는 목표를 받으면 순서를 스스로 짜고, 파일을 읽고, 명령을 실행하고, 결과를 확인해 다시 다음 단계를 정한다.
정해진 순서대로만 움직이는 워크플로우와도 다르다.
워크플로우는 사람이 미리 정한 코드 경로를 따라가고, 에이전트는 그 경로를 스스로 만든다.

매주 월요일 아침 보고서를 만들어 달라고 맡겼다고 해보자.
에이전트는 자료를 모으고, 표를 만들고, 초안을 쓰는 순서를 스스로 정해 일을 끝낸다.
챗봇이라면 매 단계마다 사람이 무엇을 해야 할지 알려줘야 한다.

쓰임은 단계가 여러 개인 일을 맡길 때이다.
반복되는 조사와 정리, 보고서 초안처럼 한 번의 질문으로 끝나지 않는 일에 어울린다.

헷갈리는 지점은 이것이다.
챗봇에 도구를 붙였다고 에이전트가 되는 것은 아니다.
다음 단계를 누가 정하는지가 갈림길이다.

```blog
type: text
runs:
  - text: "에이전트라고 해서 모든 일을 혼자 다 해내는 것은 아니다."
    style: {bold: true, background: "#FFF3CD"}
  - text: " 목표가 모호하면 중간에 멈추거나 엉뚱한 방향으로 갈 수 있다. 맡길 때는 끝낸 상태가 무엇인지 분명히 적는 편이 안전하다."
```

![마우스를 쥔 손 옆 노트북 화면에 커서와 브라우저 창이 보이는 작업 모습](images/03-img2.jpg)

마우스를 쥔 손과 커서가 보이는 노트북 화면

```blog
type: text
runs:
  - text: "컴퓨터 유즈 — "
    style: {bold: true, color: "#ff008c"}
  - text: "Claude가 스크린샷을 보고 마우스와 키보드를 직접 조종해 데스크톱과 상호작용하는 도구이다. 2024년 10월 22일, Claude 3.5 Sonnet과 함께 퍼블릭 베타로 공개됐다(Anthropic, 2024-10-22)."
```

핵심은 모델이 컴퓨터를 직접 만지는 것이 아니라는 점이다.
앱이 화면을 찍어 보내면 모델이 다음 행동을 지시하고, 앱이 실행한 뒤 새 화면을 다시 보내는 루프이다.

API로 부르는 함수 호출이 정해진 창구로 일하는 방식이라면, 컴퓨터 유즈는 사람처럼 화면을 보고 클릭하고 입력하는 방식이다.
전용 연결 창구가 없는 오래된 프로그램이나 웹사이트를 사람 대신 오가며 처리할 때 쓴다.

헷갈리는 지점은 이것이다.
컴퓨터 유즈 자체가 에이전트는 아니다.
에이전트가 쓰는 도구, 즉 손에 해당한다.

```blog
type: text
runs:
  - text: "화면에 보이는 정보가 모델에 그대로 노출된다."
    style: {bold: true, background: "#FFF3CD"}
  - text: " 비밀번호나 계좌 정보가 떠 있는 화면에서는 쓰지 않는 편이 안전하다. 샌드박스 환경에서 쓰는 것이 전제이다."
```

에이전트를 움직이는 모델도 계속 새로 나오고 있다.
[GPT-6.2 아스트라 출시](https://blog.naver.com/3700708/224483130080) 글에서 새 모델 소식을 확인할 수 있다.

    style: {bold: true, color: "#007aa6"}

![깔끔한 책상 위에서 빈 카드 세 장을 일렬로 정리하는 사람과 펼쳐진 노트, 커피잔](images/04-img3.jpg)

빈 카드 세 장을 일렬로 정리하는 책상

```blog
type: text
runs:
  - text: "에이전틱 AI — "
    style: {bold: true, color: "#ff008c"}
  - text: "에이전트와 워크플로우를 모두 아우르는 넓은 범주이다. Anthropic은 둘을 함께 'agentic systems'라는 우산 아래에 둔다(Anthropic, 2024-12-19). IBM은 여러 AI 에이전트가 제한된 감독 아래 목표에 도달하는 시스템이라고 설명한다."
```

그래서 '모든 AI 에이전트는 에이전틱 AI이지만, 모든 에이전틱 AI가 AI 에이전트인 것은 아니다'라는 말이 성립한다.
다만 업체마다 용법이 다르다는 단서를 밝혀야 한다.
같은 말을 어떤 회사는 넓게 쓰고, 어떤 회사는 좁게 쓴다.

기사나 광고에서 '에이전틱'이라는 말이 나오면, 그게 구체적인 제품인지 넓은 흐름을 말하는지 먼저 가려서 읽으면 된다.
에이전틱 AI는 제품 이름이 아니라 범주이다.
'에이전틱 AI를 샀다'는 말은 어딘가 어색하다.

| 구분 | 누가 다음 단계를 정하나 | 끝나는 지점 |
| --- | --- | --- |
| 챗봇 | 사람(질문마다) | 답을 내놓는 것 |
| 워크플로우 | 사람이 미리 정한 순서 | 정해진 단계 완료 |
| AI 에이전트 | 모델이 스스로 | 목표 달성 또는 중단 조건 |
| 컴퓨터 유즈 | 에이전트의 도구 | 화면을 보고 클릭하고 입력 |

표에서 보듯 갈림길은 하나이다.
다음 단계를 누가 정하는지, 그리고 어디에서 끝나는지이다.

```blog
type: text
runs:
  - text: "이렇게 기억하면 된다 — "
    style: {bold: true, color: "#ff008c"}
  - text: "에이전틱 AI는 넓은 말, AI 에이전트는 그 안의 하나의 시스템, 컴퓨터 유즈는 에이전트의 손이다."
```

세 용어를 나누고 보니, 뉴스를 읽을 때 덜 흔들리게 됐다.
예전에는 에이전트라는 말만 나오면 다 같은 기술인 줄 알았는데, 이제는 다음 단계를 누가 정하는지부터 보게 된다.
당장 써볼 일은 컴퓨터 유즈 쪽이 먼저일 것 같다. 오래된 프로그램 하나를 맡겨보는 식으로, 작은 일부터 손에 익혀 볼 생각이다.
용어가 정리되니 기술이 조금 덜 멀게 느껴진다. 다음에 또 새 말이 나오면, 이번처럼 정의부터 찾아볼 생각이다.

## 자주 묻는 질문

**AI 에이전트를 쓰려면 코딩을 알아야 하나요?**

아니요. 코딩 없이 채팅으로 지시만 내리면 되는 에이전트 도구도 있다. 다만 복잡한 일을 맡길수록 목표와 끝낸 상태를 글로 분명히 적는 것이 중요해진다.

**컴퓨터 유즈는 지금 누구나 쓸 수 있나요?**

2024년 10월 퍼블릭 베타로 공개된 뒤 계속 개선되고 있다. Anthropic 스스로 공개 당시 '가끔은 번거롭고 오류가 날 수 있다'고 밝혔고, 화면에 보이는 민감 정보가 모델에 노출된다는 점도 공식 문서에 적혀 있다. 쓰기 전에 공식 문서에서 현재 제공 조건을 확인하는 것이 안전하다.

**에이전트와 자동화는 같은 말인가요?**

아니다. 자동화는 정해진 순서를 반복하는 것이고, 에이전트는 상황에 따라 순서를 스스로 바꾼다. 순서가 고정돼 있으면 워크플로우나 자동화에 가깝고, 모델이 판단해 바꾸면 에이전트에 가깝다.
