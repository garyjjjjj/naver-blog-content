![클로드 코드로 디자인 잘하는 법](images/01-hero.jpg)

클로드 코드에 디자인을 맡겼는데, 결과물이 영 마음에 안 든 적 있나요.
색은 어긋나고, 여백은 어색하고, 어디가 문제인지도 모르겠는 그 느낌 말이에요.

**결론부터 말하면, 디자인은 감각의 문제가 아니라 기준의 문제다. 좋은 디자인의 기준을 스킬로 정리해 클로드 코드에게 주면, AI는 그 기준을 따라 디자인을 한다. 기준 없이 시키면 운에 맡기는 것이고, 기준을 주면 재현 가능한 결과가 나온다.**

코딩은 되는데 디자인이 늘 아쉬웠던 사람, AI가 만든 페이지가 'AI 티' 나는 게 고민인 사람이 읽으면 된다.

> **한 줄로 정리하면, 기준을 주는 쪽이 디자인을 고치는 쪽보다 먼저다. taste-skill의 세 부분(원칙·예시·체크리스트)과 cook의 여섯 가지 역할이 그 기준이다.**

클로드 코드 자체를 처음 쓴다면 [클로드 무료로 시작하는 방법](https://blog.naver.com/3700708/224474079288)에서 계정 만들고 첫 대화를 여는 순서를 먼저 확인하는 게 좋다.

```blog
type: heading
level: 2
runs:
  - text: "디자인 스킬은 왜 필요한가요?"
    style: {bold: true, color: "#007aa6"}
```

**디자인이 어려운 진짜 이유는 손재주가 아니라, 무엇이 좋은 디자인인지 판단할 기준이 없어서다. 기준이 있으면 AI도 그 기준을 따라 디자인한다.**

![디자인 스킬은 왜 필요할까](images/02-img1.jpg)

디자인 스킬을 만든 Lex는 깃허브에서 디자인 스킬 저장소를 운영하는 개발자다.
그가 처음 던진 질문은 단순하다.
"좋은 디자인인지 나쁜 디자인인지, 판단할 기준이 있나요?"
디자인이 어렵다고 느끼는 진짜 이유는 손재주가 아니라, **평가할 기준이 없어서 무엇이 문제인지 모른다**는 것이다.
그래서 그는 디자인의 기준을 정리해 스킬로 만들었다.

스킬의 속을 들여다보면 크게 세 부분으로 나뉜다.

```blog
type: text
runs:
  - text: "원칙"
    style: {bold: true, color: "#ff008c"}
  - text: " — 디자인을 할 때 지켜야 할 규칙들이다. 기본 원칙, 심화 원칙, 실전 원칙 세 가지로 나뉜다."
```

```blog
type: text
runs:
  - text: "예시"
    style: {bold: true, color: "#ff008c"}
  - text: " — 좋은 디자인과 나쁜 디자인의 예시가 들어 있다. 어떤 게 좋고 어떤 게 나쁜지, 눈으로 직접 비교할 수 있다."
```

```blog
type: text
runs:
  - text: "체크리스트"
    style: {bold: true, color: "#ff008c"}
  - text: " — 디자인을 다 만들고 나서 체크해야 할 항목들이다. 색상, 타이포그래피, 레이아웃, 간격 같은 디자인의 모든 기준이 들어 있다."
```

이 세 가지를 같이 보면, **디자인을 평가할 눈이 생긴다**.

스킬의 정체는 이렇다.
깃허브 저장소 Leonxlnx/taste-skill, **별 116,141개(2026-11-16 GitHub API 직접 확인)**다.
깃허브 설명은 "코딩 에이전트에게 취향을 주는 에이전트 스킬"이다.
아트 디렉션, 레퍼런스 이미지, 그리고 브라우저로 직접 확인하는 방식이 들어 있다.
AI가 만든 흔한 페이지가 아니라, **디자이너가 검수한 페이지에 가깝게 만드는 것**이 목표다.
무료 오픈소스라 깃허브에서 누구나 받아서 쓸 수 있다.

```blog
type: heading
level: 2
runs:
  - text: "cook은 무엇이고, 여섯 가지 역할은 무엇인가요?"
    style: {bold: true, color: "#007aa6"}
```

**cook은 클로드 코드에서 디자인을 할 수 있게 해주는 에이전트 앱이다. taste-skill의 기준을 가지고 실제 디자인 작업을 돕는다.**

![cook의 여섯 가지 역할](images/03-img2.jpg)

taste-skill과 함께 공개된 것이 cook이다.
깃허브 저장소 Leonxlnx/cook에서 받아 설치하면 클로드 코드에서 쓸 수 있다.
cook의 깃허브 설명은 "에이전트에게 목표와 기준, 시간을 주고 맡기는" 스킬이다.
레퍼런스 이미지나 영상과 일치해야 하는 시각 작업에 쓰는 도구다.

cook은 크게 여섯 가지 역할을 한다.


```blog
    style: {bold: true, color: "#ff008c"}
```

```blog

    style: {bold: true, color: "#ff008c"}
```


이 여섯 가지가 합쳐지면 디자인이 잘 나온다는 것이 영상의 설명이다.

구조는 간단하다.
클로드 코드가 디자인을 할 때, cook이 옆에서 도와주는 구조다.
어떤 색을 써야 하는지, 어떤 폰트를 써야 하는지, **필요한 정보를 cook이 제공한다**.
그래서 클로드 코드가 디자인할 때 헤매지 않는다는 것이다.
여기까지는 영상과 깃허브 설명이 일치하는 부분이다.

```blog
type: text
runs:
  - text: "실제로 얼마나 잘 나오는지는, 영상 속 시연 장면 하나로 단정할 수 없다."
    style: {bold: true, background: "#FFF3CD"}
  - text: " 직접 한 번 돌려보고 내 눈으로 확인하는 것이 순서다."
```

```blog
type: table

  - [{text: "cook", width: 18}, {text: "기준을 가지고 디자인 작업을 돕는 에이전트 앱 — 여섯 가지 역할(원칙 전달·예시 제공·피드백·수정 방향·완성도 향상·일관성 유지)", width: 82}]
```

AI에게 웹사이트를 맡겨본 경험이 있다면 [바이브코딩 웹사이트 티어표](https://blog.naver.com/3700708/224475162723)에서 1티어 기능이 클로드 손에서 어떻게 구현되는지 먼저 보는 것도 도움이 된다.

```blog
type: heading
level: 2
runs:
  - text: "cook에게 디자인을 시키는 방법은?"
    style: {bold: true, color: "#007aa6"}
```

**사용법 자체는 간단하다. 클로드 코드에서 cook을 실행하고, 원하는 디자인을 구체적으로 요청하면 된다.**

![cook에게 시키는 방법](images/04-img3.jpg)

만들고 나서 마음에 안 드는 부분이 있으면, cook에게 수정을 요청하면 된다.
그러면 cook이 수정을 해준다.

다만 요청하는 방식에 요령이 있다.
**구체적으로 요구해야 한다.**
'이 페이지의 디자인을 해줘'가 아니라, '이 페이지의 히어로 섹션을 모던한 스타일로 디자인해줘'처럼 구체적으로 말해야 한다.
구체적으로 말할수록 cook이 더 좋은 디자인을 만들어준다는 것이 영상의 조언이다.
이 조언은 디자인 스킬의 원칙과도 맞물린다.
**기준이 구체적일수록 결과도 구체적이 된다.**

영상에서는 실제로 cook을 실행해 디자인하는 장면도 보여준다.
색상도 잘 맞고, 레이아웃도 잘 맞고, 타이포그래피도 잘 맞았다는 것이 영상의 평가다.

```blog
type: text
runs:
  - text: "이 평가는 영상을 만든 쪽의 주장이라는 점을 구분해 둘 필요가 있다."
    style: {bold: true, background: "#FFF3CD"}
  - text: " 내가 직접 확인할 수 있는 사실은 따로 있다. 스킬과 앱이 공개돼 있고, 별 11만 개가 넘는 저장소가 실제로 존재하며, 설치해서 바로 써볼 수 있다는 점이다."
```

오늘 할 일은 하나다.
깃허브에서 taste-skill과 cook을 받아, **평소에 아쉬웠던 내 페이지 하나에 적용해보는 것**이다.
그 결과물이 좋아졌는지, 어디가 달라졌는지는 내 눈으로 판단하면 된다.

```blog
type: heading
level: 2
runs:
  - text: "마무리"
    style: {bold: true, color: "#007aa6"}
```

AI가 만든 페이지가 늘 어딘가 아쉽게 느껴졌던 이유가, 모델이 못해서가 아니라 기준이 없어서였다는 말이 오래 남았다.
디자인을 평가할 눈이 생기면, AI에게 시키는 말도 달라진다.
오늘은 taste-skill 하나를 받아 내 페이지에 적용해보는 것부터 시작하면 된다.

## 자주 묻는 질문

**taste-skill은 어디서 받나요?**
깃허브 저장소 Leonxlnx/taste-skill에서 받을 수 있다.
별 116,141개(2026-11-16 확인)의 오픈소스 스킬이다.

**cook은 taste-skill과 뭐가 다른가요?**
taste-skill은 디자인 기준이 담긴 스킬이고, cook은 그 기준을 가지고 실제 디자인 작업을 돕는 에이전트 앱이다.
둘 다 같은 개발자(Lex)가 공개했고, 함께 쓰도록 설계됐다.

**클로드 코드가 꼭 필요한가요?**
영상에서 소개한 방식은 클로드 코드를 전제로 한다.
스킬과 cook 모두 클로드 코드에서 디자인을 돕는 도구다.

**돈이 드나요?**
스킬과 cook 자체는 깃허브에 공개된 무료 자료다.
클로드 코드 사용 요금은 별도다.

**디자인을 몰라도 쓸 수 있나요?**
쓸 수 있다.
영상의 추천 이유는 디자인을 모르는 사람도, 잘하는 사람도 cook을 쓰면 디자인을 더 잘할 수 있다는 것이다.
다만 결과물은 내 눈으로 직접 검수하는 것이 좋다.
