# 프로그램–뮤즈 MCP 직접 소통 전환 기록

사용자 최신 결정: 프로그램–뮤즈 소통은 MCP 직접 메시지, GitHub는 원고·기록 보관. COMMUNICATION.md의 2026-10-20.1 계약을 적용합니다. 프로그램 소스는 업로드하지 않았습니다.

## 확인된 결과

- 설치된 MCP 0.3.0에서 send_message / receive_messages / ack_message 제공. 기존 HTTPS 주소와 뮤즈별 인증을 유지합니다.
- 지속 SQLite 메시지함, 고유 request_id에 따른 재접수 중복 방지/내용 충돌 거절, 뮤즈별 읽기·답변·ACK 권한 분리, 처리 커서와 수신 확인을 구분합니다.
- 개발 클라이언트의 외부 통신 시험은 실제 뮤즈 수신 보고와 별도로 표시했습니다.
- muse-01: 전환 안내 메시지(seq10)에 실제 ACK, reply_to를 연결한 전환 보고(seq11) 및 후속 운영 메시지(seq13/14)를 프로그램이 받았습니다. 가동 알림 2건도 실제 ACK를 확인했습니다.
- muse-02: 가동 알림 2건에 실제 ACK, MCP 도구 허용 목록 추가와 직접 소통 채택 보고(seq12)를 프로그램이 받았습니다.
- 프로그램 UI에서 MCP/GitHub 기록, 저장 대기/실제 수신 확인/받은 답변/처리 보류를 구분합니다. 정상 조회와 단순 ACK는 AI 호출을 만들지 않습니다.
- 이미 정상 발행된 글의 과거 오류 문의 3건은 해결로 처리하고 MCP 재전달 대상에서 제외했습니다. 기록은 보존합니다.

## 발행 대조 변경

정상 건은 본문·이미지·서식·제목·카테고리·공개 범위·원본 버전·게시 URL 자동 비교만으로 완료합니다. 차이가 있으면 위치·원본·실제를 기록하고 필요한 예외 원인 분석/문의만 AI를 사용합니다. 시각 문제는 실제 게시 화면과 원고/원본 이미지로 렌더링한 참고 화면을 첨부합니다. AI 설명은 확정된 불일치를 무시할 수 없습니다. 글 내용의 사실관계·문체를 심사하지 않습니다.

기존 공개글 1건(새로 나온 테크)의 읽기 전용 자동 대조가 차이 없음으로 통과했습니다. 이 확인에서 AI 호출 0회, 게시/수정 0회였습니다. 경로 탐색·기존 연결 설정 재사용 수정 후 프로그램의 실제 Codex 계정/사용량/모델 조회도 정상입니다.

## 아직 구분할 제약

- MCP 도구·실제 메시지 왕복 확인은 완료됐지만, 두 Muse의 무인 상시 감지가 검증된 것은 아닙니다.
- muse-01 최초 보고: 5분 LLM 예약 실행에 의존, 비LLM 60초 스크립트 감지 미지원. 후속 메시지에 감시 전환을 보고했지만 예약 실행 실증과는 구분합니다.
- muse-02 보고: 정기 작업/대화 활동 시 메시지를 확인, 상시 폴링 미구현. GitHub 쓰기는 live 턴에서만 가능하고 백그라운드에서는 거부된 사례가 있습니다.
- 프로그램이 임의로 원격 에이전트를 깨울 수는 없습니다. 각 Muse에 비LLM 조회/웹훅 수신/공식 메시지 API의 실제 지원 여부·제약을 MCP로 문의했습니다. 미지원/승인 제약을 우회하지 않습니다.
- 프로그램 전용 GitHub 쓰기 인증은 현재 없습니다. 메시지 원문과 상태는 로컬 지속 DB·전체 이력 내보내기에 보존되며, 이 문서는 개발 채팅 연결로 남긴 전환 요약입니다. 이후 모든 메시지가 자동으로 GitHub에 동기화된다고 주장하지 않습니다. 원고·이미지는 기존 GitHub 저장 방식 유지.
- Windows 자동 시작은 로그인 후 바로가기 등록 상태입니다. 로그인 전 부팅 작업과 실제 재부팅 실증은 별도 미완료입니다.
- 원격 메시지는 명령 실행·권한 변경·추가 발행 허가가 아닙니다. 블랙박스 기존 중복 제외 원고는 이번 작업으로 새로 발행하지 않았습니다.
