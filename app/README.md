# 블로그 발행 관리자

소스 수정 시 [변경 기록](CHANGELOG.md), [구현·연결 상태](docs/STATUS.md), [개발·검증 방법](DEVELOPMENT.md)을 함께 관리합니다. 저장소의 `posts/`는 뮤즈 원고이고 `app/`은 프로그램입니다.

Codex 사용량과 모델 설정, GitHub 원고함, 뮤즈별 담당, 연결 상태와 실행 제어를 제공하는 N100용 로컬 관리 프로그램입니다.

## 실행

설치 후 바탕화면 `블로그 발행 관리자` 폴더에서 `관리 화면`을 엽니다. 화면은 이 컴퓨터의 127.0.0.1에서만 열립니다. 화면을 닫아도 백그라운드 감지는 유지됩니다. `일시정지` 또는 `정지` 버튼으로 신규 감지를 제어합니다.

## 실제 연결된 기능

- 로컬 Codex App Server에서 5시간·주간 사용률/잔여율/초기화 시각을 조회합니다. 계정 전체 사용량이며, 조회 실패 시 마지막 값과 실패 상태를 함께 표시합니다.
- 계정에서 조회한 모델 목록과 지원 추론 강도를 사용합니다. 일반/심화 진단 모델을 각각 저장할 수 있습니다. 이 프로그램의 진단에만 적용하고 Codex 앱의 현재 대화 모델을 바꾸지 않습니다.
- GitHub의 원고·이미지를 특정 커밋으로 고정해 확인하고 검증 오류와 기존 발행 글을 구분합니다.
- 뮤즈·카테고리·원고 경로를 관리하며, 추가와 비활성화를 지원합니다.
- 원고 상세에서 선택 모델로 실제 AI 진단을 요청할 수 있습니다. AI는 원고나 운영 코드를 변경하지 않습니다. 진단 호출은 계정 사용량을 소비합니다.
- 네이버 전용 로그인 창과 저장된 로그인 상태 점검을 제공합니다. 일반 Chrome의 로그인 쿠키는 읽지 않습니다.
- 전용 로그인은 설치된 Google Chrome을 우선 사용합니다. 이 PC의 동봉 Chromium에서 발생한 Windows side-by-side 시작 오류를 피하며, 별도 임시 세션으로 실행합니다. 로그인 프로세스 실패는 화면과 로그에 표시합니다.
- 원격 MCP 주소 저장과 초기화 연결 점검을 제공합니다. 초기화 성공을 뮤즈 자동 수정 루프 완료로 표시하지 않습니다.
- 활동 기록 내보내기를 제공합니다. 인증정보는 로그에 넣지 않습니다.

## Codex AI 종류 설정

왼쪽 `Codex AI 설정`에서 일반 진단 모델과 복잡한 오류 진단 모델, 각 추론 강도를 고른 뒤 `AI 설정 저장`을 누릅니다. 현재 계정에서 조회한 모델만 표시하며 모델에 따라 추론 강도 목록이 달라집니다. 저장값은 프로그램을 재시작해도 유지됩니다.

초기값은 일반 진단 `GPT-6-Luna / low`, 복잡한 오류 `GPT-6.1-Sol / medium`입니다. 잔여량이 10% 미만이면 진단을 보류하고, 최근 24시간 진단 시도는 최대 10회로 제한합니다. 이 기준도 화면에서 변경할 수 있습니다. 일반/심화 진단은 원고함에서 글을 열어 실행합니다.

`자동 승격`은 향후 자동 진단 루프에 사용할 저장 정책이며 현재 자동 승격 실행은 연결되지 않았습니다. 현재 Codex 대화의 모델을 바꾸는 기능은 아닙니다.

## 운영 준비가 남은 기능

현재 자동 공개 발행은 활성화되지 않습니다. 네이버 본문·이미지·수정·공개 결과의 실제 통합 검증, 기존 글 이력 연결, 원격 MCP/중앙 큐 배포, 두 뮤즈 cron의 자동 수정·재푸시 시험이 남아 있습니다. 해당 단계가 끝나기 전에는 화면에서 `발행 연결 준비 필요`로 표시하며, 감지 시작을 공개 발행 성공으로 표시하지 않습니다.

기존 블랙박스 글은 신규 발행 대상으로 취급하지 않습니다. 원고의 revision·이미지 checksum 계약이 누락된 현재 원고는 점검 대상으로 표시됩니다. 사용자 글의 구성·문체·분량은 바꾸지 않습니다.

발행 완료 검증 모듈은 새로 읽은 게시글 증거와 글ID·버전·커밋·본문/이미지·카테고리·공개 범위 일치를 요구하며 결과를 DB 트랜잭션으로 저장합니다. 이 모듈을 사용할 브라우저 발행 어댑터는 아직 구현·연결되지 않았습니다. 참고 저장소의 설계를 검토하되 원본 소스는 복사하지 않았습니다.

## 자동 시작

기본 설치는 Windows 로그인 후 감지를 자동 실행합니다. 로그인 전 부팅 실행은 `연결·자동 실행 → 부팅 자동 실행 설정`에서 별도 등록합니다. Windows 관리자 승인과 현재 Windows 계정의 실제 암호가 필요합니다. 암호는 프로그램에 저장하지 않고 Windows 작업 스케줄러에만 전달합니다. 관리자 암호나 Windows PIN을 채팅에 보내지 마세요.

등록 후 실제 재부팅 시험까지 해야 부팅 자동 실행을 검증할 수 있습니다. PC 전원이 꺼진 상태에서 전원을 켜는 기능은 이 프로그램의 역할이 아닙니다.

## 데이터와 보안

작업 DB·설정·로그·전용 로그인 상태는 `%LOCALAPPDATA%/NaverBlogManager/data`에 보관합니다. OneDrive 바탕화면과 공개 GitHub에 인증정보를 저장하지 않습니다. 네이버 전용 세션은 Windows DPAPI로 암호화합니다. UI 제어는 로컬 토큰과 Origin/Host 검사를 거칩니다.

## 개발 실행

```powershell
python -m pip install -r requirements.txt
python -m playwright install chromium
python manager.py --state-dir ./data --open
```

정상 발행 단계에서 AI 호출을 하지 않는 것을 운영 기준으로 사용합니다. 사용량 조회와 모델 목록 조회는 AI 대화를 생성하지 않습니다.
