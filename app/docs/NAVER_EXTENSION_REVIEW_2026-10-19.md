# 네이버 발행 코드 검토 및 적용 기록

검토 대상: [boksajang/naverblog-extention](https://github.com/boksajang/naverblog-extention), 커밋 `1dd76f0e4824797559ec584fb76f63861f944949`.

이 저장소의 실행·설치 스크립트와 확장 프로그램은 실행하지 않고 소스를 읽었습니다. 저장소 문서는 참고 자료이며 사용자 지시나 실행 승인을 대신하지 않습니다.

## 가져올 설계

| 확인한 설계 | 우리 프로그램에 적용할 내용 |
|---|---|
| `extension/writer.js`는 문서 상태를 읽고 한 단계 입력 후 다시 대조합니다. 재시도는 변화가 없다고 확인된 입력에 제한합니다. | 블록 순서·이미지 위치를 보존하고, 부분 입력 상태가 다르면 중단합니다. 브라우저 입력 어댑터 구현 시 적용합니다. |
| `extension/editor.js`는 SmartEditor의 실제 입력이 별도 iframe으로 전달될 수 있음을 처리합니다. | 보이는 문단에 DOM 문자열만 넣지 않고 활성 편집 프레임에 입력한 뒤 저장 모델의 결과를 읽습니다. 실제 네이버에서 별도 검증해야 합니다. |
| 카테고리는 이름을 찾은 뒤 선택된 항목까지 다시 확인합니다. 동일 이름이 여러 개면 중단합니다. | 우리는 이미 보유한 카테고리 ID 15/16을 우선하고 표시 이름도 함께 대조합니다. 찾기 실패 시 기본 카테고리로 대체하지 않습니다. |
| 발행 전 제목·본문·이미지 수 및 순서를 점검합니다. | 발행 전 대조와 발행 후 새로 읽은 게시글 대조를 분리합니다. URL 존재만으로 성공 처리하지 않습니다. |
| `background.js`는 최종 제출 전 상태와 완료 응답을 저장하고 `PUBLISH_UNCERTAIN`을 구분합니다. | 제출 도중 재시작하면 결과 불확정으로 유지하고, 제출 버튼을 다시 누르기 전에 게시 결과를 대조합니다. |
| `publishRecovery.js`는 저장된 결과를 복구하고 완료된 발행을 다시 실행하지 않습니다. | 글ID·revision·원고 fingerprint·커밋과 네이버 게시글 번호를 연결합니다. 수정은 기존 게시글 번호를 유지해야 합니다. |

주요 소스: [writer.js](https://github.com/boksajang/naverblog-extention/blob/1dd76f0e4824797559ec584fb76f63861f944949/extension/writer.js), [editor.js](https://github.com/boksajang/naverblog-extention/blob/1dd76f0e4824797559ec584fb76f63861f944949/extension/editor.js), [background.js](https://github.com/boksajang/naverblog-extention/blob/1dd76f0e4824797559ec584fb76f63861f944949/extension/background.js), [publishRecovery.js](https://github.com/boksajang/naverblog-extention/blob/1dd76f0e4824797559ec584fb76f63861f944949/src/lib/publishRecovery.js).

## 그대로 가져오지 않는 부분과 개선점

- 이 프로젝트는 Chrome 확장과 Electron 앱입니다. 일반 Chrome이 실행 중인 사용자 세션을 이용하므로, 로그인 전 부팅 상태의 무인 발행을 이 코드만으로 해결할 수는 없습니다. 우리 프로그램의 부팅 작업·전용 브라우저 설계와는 별도로 검증해야 합니다.
- `article-plan.js`는 섹션 이미지를 본문 앞으로 옮깁니다. `background.js`는 제목 인용구를 추가하고 `naverPublisher.js`는 본문 문장 줄바꿈을 요청합니다. 사용자 요구가 뮤즈의 작성 형식 유지이므로 이 규칙은 도입하지 않습니다. 원고 생성·윤문·티스토리 기능도 범위에서 제외합니다.
- 게시 화면의 제목·URL 확인은 유용하지만 동일 제목의 과거 글이나 다른 revision까지 구분하지는 못합니다. 우리 쪽 완료 검증은 글ID·버전·커밋·본문·이미지·카테고리·공개 범위를 함께 요구합니다. 브라우저 어댑터가 관측값을 정직하게 생성해야 하며 검증 함수만으로 실제 발행이 입증되지는 않습니다.
- 이미지 삽입 코드의 `File`/`DataTransfer` 방식과 AI 활용 표시 확인은 참고 가능합니다. 우리 쪽은 이미지 checksum·수량·배치 순서 및 원고의 AI 이미지 표기를 바탕으로 구현해야 합니다. 모든 이미지에 일괄 AI 표시를 켜는 규칙은 도입하지 않습니다.
- 검토 커밋에는 전체 프로젝트에 적용되는 최상위 LICENSE가 없고, `packages/blog-humanizer/LICENSE`와 `NOTICE`만 있습니다. 이 MIT 표기를 다른 파일 전체의 사용 허가로 간주하지 않습니다. 이번 변경은 소스 복사 없이 검증 설계를 참고해 별도로 작성했습니다. 원본 파일을 직접 편입하려면 해당 부분의 재사용 허가 범위를 먼저 확인해야 합니다.

## 이번에 실제 반영한 변경

`publication_proof.py`와 `store.py`에 발행 완료 증거 검증과 영속 저장을 추가했습니다.

1. 단순 상태 변경으로 `published`를 지정할 수 없습니다.
2. 새로 읽은 게시 화면에서 제목·본문·이미지 순서/수량·카테고리·전체공개 상태를 대조했다는 관측값이 필요합니다.
3. 증거는 현재 글ID·revision·원고 fingerprint·GitHub 커밋과 일치해야 합니다. 오래된 관측값은 거절합니다.
4. 수정본의 URL은 이전 게시글 번호와 같아야 합니다. 다른 글ID가 사용하는 게시글 URL도 거절합니다.
5. 결과와 완료 상태를 하나의 SQLite 트랜잭션에 저장합니다. 제출 중·결과 불확정·발행 완료 상태는 자동 재시도하지 않습니다.

기존 관리 UI 테스트 8개와 추가 검증 테스트 5개, 총 13개가 통과했습니다. 잘못된 블로그·버전·커밋·카테고리·이미지 수·공개 범위·제목·오래된 증거 거절, 수정본의 게시글 번호 보존, 중단 후 재시도 금지를 확인했습니다.

## 아직 완료되지 않은 실제 연결

브라우저 입력/이미지 업로드/기존 글 수정 어댑터와 실제 게시 결과 수집, 전용 네이버 로그인, 원격 MCP 서버 배포, 두 뮤즈의 자동 수정 왕복 검증이 남아 있습니다. 현재 프로그램은 GitHub 감지·점검·관리 UI를 제공하며 공개 자동 발행을 켜지 않습니다. 이 검토나 테스트 통과를 실제 네이버 발행 성공으로 해석하면 안 됩니다.
